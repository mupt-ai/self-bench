## Subagent Models

On the Run page, expand **Subagent Model** beneath a Codex or Claude Code configuration and enable **Override Subagent Model**. Choose a model and a matching credential independently of the parent model. The same option is available for benchmark runs.

For API requests, add `subagent` to a model row:

```json
{
  "catalogId": "<parent-catalog-id>",
  "credentialId": "<parent-credential-uuid>",
  "harnesses": ["claude-code"],
  "subagent": {
    "catalogId": "<subagent-catalog-id>",
    "credentialId": "<subagent-credential-uuid>"
  }
}
```

Both models must support the selected credential route on every selected harness. Use the catalog ID returned by the catalog API, not a guessed provider model ID. Managed model access uses `managed-model` as the credential ID where available. Omit `subagent` to preserve each harness's existing defaults.

For Claude Code, the override sets `CLAUDE_CODE_SUBAGENT_MODEL` after Harbor constructs its environment. For Codex, it sets `agents.enabled = true` and `agents.default_subagent_model` in the gateway's effective Codex configuration. Codex uses its existing Responses endpoint for both models; explicit spawn settings or custom agents can override the default, but requests are still restricted to the signed model allowlist. Claude Code still decides whether to delegate based on the task, its built-in agents, and available custom agent descriptions. Ask it to delegate explicitly in the task instruction when needed; selecting a model does not force subagent use or inject an agent prompt.

The gateway key authorizes exactly the parent and configured secondary model. It does not grant provider-wide access or expose either provider credential in the sandbox. This is a model allowlist, not a security distinction between parent and subagent processes: either can request either authorized model. Judge access stays on a separate key.

Subagent calls are included in the trial's gateway cost, using each call's actual model. A mixed-model run is left unpriced if a call cannot be priced; it is never estimated using only the parent's rates. Mixed-model runs do not report a separate billed total, because the two credentials may mix API billing and subscription access. Results, completed-task skipping, and retries preserve the subagent configuration.

### Harness Support

Every harness shows its support status rather than silently accepting an unused option:

| Harness | Configurable Secondary Model |
| --- | --- |
| Codex | Yes, through its native subagent model default. |
| Claude Code | Yes, through its native subagent model override. |
| Pi | Not in the stock Harbor adapter: no delegation extension is installed. |
| Mini-SWE-Agent | No native delegated-agent model option in this adapter. |
| Terminus 2 | Internal summarization calls are not configurable task-delegation agents here. |
| Muse Code | Internal delegation exists, but no verified independent model override or gateway route in this integration. |

Unsupported harnesses reject a supplied `subagent` configuration at comparison creation. Enabling delegation on them would require a separate tool or harness extension, not just selecting a model.

Returns `202` with comparison status. Fetch tasks from `GET …/evaluations/options`, models and sandboxes from `GET …/evaluations/catalog`, and status from `GET …/evaluations/comparisons/{id}`. If `submissionError` is present, resume the same comparison at `POST …/comparisons/{id}/resume`.
