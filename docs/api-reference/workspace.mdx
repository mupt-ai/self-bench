Everything the app does with your evals is a JSON request to `https://app.selfbench.dev`. The [CLI](/cli/overview) wraps the same routes.

```bash
export SELFBENCH_API_KEY=sbk_…
curl https://app.selfbench.dev/api/me -H "Authorization: Bearer $SELFBENCH_API_KEY"
```

A key acts as its owner, with the owner's workspace roles. `read` keys may only `GET`. See [API Keys](/api-reference/api-keys).

## Conventions

- **Scopes.** Evaluation routes live under a scope, written `{scope}` below:
  - a repository or eval: `/api/orgs/{org}/repos/{owner}/{name}` (an eval's owner is `evals`)
  - a Harbor benchmark: `/api/orgs/{org}/benchmarks/{dataset-org}/{dataset}`
  - a repository group: `/api/orgs/{org}/groups/{slug}`

  `{repo}` means the repository form only.
- **Tasks** are named by their batch and ID, `{runId}/{taskId}`.
- **Configurations** (model, reasoning, harness) are named by a setting `key`, which [results](/api-reference/results), [model summaries](/api-reference/failure-analysis#model-summaries), and [releases](/api-reference/publish-release) share.
- **Background work.** Generation, evaluations, explanations, audits, and summaries return `202` and run on workers. Poll the matching `GET` route.
- **Errors** are JSON: `{ "error": "…" }`. Expect `400` for invalid input, `403` when the key may not do it, `404` when it isn't there, and `409` when the current state doesn't allow it.

## Every Route

| Stage | Method | Route | Does |
| --- | --- | --- | --- |
| Account | `GET` | `/api/me` | Caller, workspaces, and key scope |
| | `GET` | `/api/orgs/{org}/credentials` | Saved model and sandbox credentials |
| Repositories | `GET`, `POST` | `/api/orgs/{org}/repos` | [List or connect](/api-reference/repositories) repositories |
| | `GET`, `PATCH`, `DELETE` | `{repo}` | Read, configure, or disconnect one |
| | `POST` | `/api/orgs/{org}/evals` | Create a workspace eval |
| | `GET` | `{repo}/pull-requests?page=N` | Merged pull requests |
| Build | `GET` | `{repo}/generation-options` | Models, sandboxes, and credentials for generation |
| | `GET`, `POST` | `{repo}/batches` | [List or start](/api-reference/create-batch) batches |
| | `GET` | `{repo}/batches/{runId}` | A batch's progress |
| | `POST` | `{repo}/batches/{runId}/cancel` | Stop a batch |
| | `POST` | `{repo}/tasks/from-pr` | [A task from one PR](/api-reference/create-batch#one-pull-request) |
| | `POST` | `{repo}/tasks/from-scenario` | [A task from a scenario](/api-reference/create-scenario) |
| Review | `GET` | `{repo}/tasks` | [List tasks](/api-reference/tasks) |
| | `GET`, `DELETE` | `{repo}/tasks/{runId}/{taskId}` | Read or delete a task |
| | `GET` | `{repo}/tasks/{runId}/{taskId}/draft` | Its files, as `.tar.gz` |
| | `GET` | `{repo}/tasks/{runId}/{taskId}/artifacts` | Its gate and review artifacts |
| | `PUT`, `DELETE` | `{repo}/tasks/{runId}/{taskId}/review` | Approve or reject, or clear the review |
| | `POST` | `{repo}/tasks/{runId}/{taskId}/feedback` | Revise it from feedback and edited files |
| | `POST` | `{repo}/tasks/{runId}/{taskId}/cancel` | Stop its generation |
| Evaluate | `GET` | `{scope}/evaluations/catalog` | [Models and sandboxes](/api-reference/create-comparison) |
| | `GET` | `{scope}/evaluations/options` | Tasks a comparison can run |
| | `GET`, `POST` | `{scope}/evaluations/comparisons` | List or start comparisons |
| | `GET` | `{scope}/evaluations/comparisons/{id}` | A comparison's progress |
| | `POST` | `{scope}/evaluations/comparisons/{id}/resume` · `/cancel` | Resume or stop it |
| | `GET` | `{scope}/evaluations` | Evaluations, one per model, with every trial |
| | `GET` | `{scope}/evaluations/{id}` | One evaluation |
| | `POST` | `{scope}/evaluations/{id}/cancel` · `/delete` | Stop or delete it |
| Inspect | `GET` | `{scope}/evaluations/results` | [Scores, and each task's results](/api-reference/results) |
| | `GET`, `POST` | `{scope}/evaluations/{id}/explain` | [Explain a failed trial](/api-reference/failure-analysis) |
| | `GET`, `POST` | `{scope}/evaluations/audit` | [Audit a task's fairness](/api-reference/failure-analysis#task-audits) |
| | `GET`, `POST` | `{scope}/evaluations/summaries` | [Model summaries](/api-reference/failure-analysis#model-summaries) |
| Publish | `GET`, `POST` | `{repo}/releases` · `/api/orgs/{org}/groups/{slug}/releases` | [List or publish](/api-reference/publish-release) releases |
| | `GET` | `…/releases/preview` | What a release would publish |
| | `POST` | `…/releases/{id}/withdraw` | Withdraw one |
| Benchmarks | `GET`, `POST` | `/api/orgs/{org}/benchmarks` | [List or add](/api-reference/create-benchmark) Harbor datasets |
| | `GET`, `DELETE` | `/api/orgs/{org}/benchmarks/{dataset-org}/{dataset}` | Read or remove one |
| | `GET` | `…/benchmarks/{dataset-org}/{dataset}/tasks` | Its tasks |
| Groups | `GET`, `POST` | `/api/orgs/{org}/groups` | [List or create](/api-reference/create-benchmark#repository-groups) groups |
| | `GET`, `PUT`, `DELETE` | `/api/orgs/{org}/groups/{slug}` | Read, edit, or delete one |

## Model Costs

Evaluation trials call their model through SelfBench's model gateway. It uses the workspace credential for the trial and records each call's cost: the provider's own charge where it reports one (OpenRouter, Vercel AI Gateway), else the model's list price. A trial with a call neither prices shows its cost as incomplete. The credential itself never reaches Harbor or the agent, which holds only a short-lived key for that one model.

For a self-hosted deployment, replace the app origin with your own. Released results can also be read without a key through the [Public Results API](/api-reference/overview).
