Install and first steps are in the [Quickstart](/quickstart). `self-bench help` lists the same commands in your terminal.

## Sign In and CI

`login` saves a personal API key to `~/.config/self-bench/config.json`, readable only by you. On a remote machine, paste the address the browser lands on into the login page. `logout` revokes the key.

In CI, skip `login` and set `SELFBENCH_API_KEY` (from **Settings → API Keys**) and `SELFBENCH_ORG`. `SELFBENCH_API_URL` or `login --api-url` points at a self-hosted deployment.

## Conventions

- **Workspace.** Commands act in the workspace `login` chose. `org use` changes it; `--org` overrides it once.
- **Scope.** `R` below is `--repo OWNER/NAME`. An eval is `evals/NAME`. `--benchmark ORG/NAME` and `--group SLUG` take its place.
- **Tasks** are named by batch and ID: `RUN_ID TASK_ID`.
- **Configurations** are named by the `KEY` that `results` prints.
- **Output.** Tables on a terminal, JSON when piped or with `--json`, so `self-bench results --repo acme/app | jq` works.
- **Background work.** Explanations, audits, and summaries return at once. Add `--wait` to wait and print the answer.

## Account

| Command | Does |
| --- | --- |
| `login [--api-url URL] [--no-browser]` | Sign in through the browser; saves a key and the workspace |
| `org` · `org use [NAME]` | Show or change the workspace |
| `whoami` | The account, its workspaces and roles, and the key's scope |
| `logout` | Revoke the saved key and forget it |

## Credentials

Workspace admins connect the model access and sandboxes runs use. Secrets never go in an argument, so they stay out of shell history.

| Command | Does |
| --- | --- |
| `credentials` | Saved credentials, with the IDs flags take |
| `credential add` | Pick a provider, then paste its key (masked) or sign in |
| `credential add --kind KIND (--value-env VAR \| --value-stdin) [--name NAME]` | Add a key without prompts |
| `credential add --sign-in chatgpt\|claude\|meta` | A ChatGPT, Claude, or Meta sign-in |
| `credential rename ID NAME` · `credential remove ID` | Rename or remove one |

`KIND` is `openai`, `anthropic`, `meta`, `openrouter`, `vercel-ai-gateway`, `dari`, `custom` (with `--endpoint`), `e2b`, `modal` (with `--token-id`), `daytona`, or `vercel` (with `--team-id` and `--project-id`). See [Credentials](/concepts/credentials).

## Build

| Command | Does |
| --- | --- |
| `repos` | Connected repositories and evals |
| `repo connect\|show\|disconnect R` | Connect, read, or disconnect a repository |
| `repo set R --agent-minutes N` | How long an agent may work on each task |
| `eval create NAME` | A workspace eval; then use `--repo evals/NAME` |
| `prs R [--page N]` | Merged pull requests |
| `generate R --easy N --medium N --hard N [--focus TEXT]` | Start a batch that picks PRs and authors tasks |
| `task add-pr R --pr NUMBER\|URL` | A task from one merged PR |
| `scenario create R --title T (--scenario TEXT \| --scenario-file F) [--commit REF] [--attach F ...] [--difficulty D]` | A task from a described scenario |
| `batches R` · `batch show\|cancel RUN_ID R` | Follow or stop batches |

`generate`, `task add-pr`, `scenario create`, and `task revise` take `--model`, `--verifier-model`, `--reasoning`, `--model-credential`, `--sandbox`, `--sandbox-credential`, `--harbor`, and `--harbor-credential`, or `--generation JSON\|@FILE`. Without them, they use managed models and sandbox.

## Review

| Command | Does |
| --- | --- |
| `tasks R [--state S]` | `S` is `needs_review`, `accepted`, `rejected`, `in_progress`, `failed`, or `cancelled` |
| `task show RUN_ID TASK_ID R` | A task, its review, cost, and revisions |
| `task pull RUN_ID TASK_ID [DIR] R` | Download its files: instruction, Dockerfile, patches, scripts, `workspace/` |
| `task revise RUN_ID TASK_ID R (--feedback TEXT \| --feedback-file F) [--draft DIR]` | Revise from feedback; `--draft` sends your edited files too |
| `task steer RUN_ID TASK_ID R (--feedback TEXT \| --feedback-file F)` | A note to a task still generating; its author reads it at its next turn |
| `task steering RUN_ID TASK_ID R` | The notes sent, and which turn received each |
| `task approve\|reject RUN_ID TASK_ID R [--note TEXT]` | Review it; only approved tasks are evaluated |
| `task unreview\|cancel\|delete RUN_ID TASK_ID R` | Clear the review, stop generation, or delete |

## Evaluate

| Command | Does |
| --- | --- |
| `catalog R` | Models available for evaluations |
| `compare R --model ID [--model ID ...]` | Run each model on every approved task |
| `comparisons R` · `comparison show\|resume\|cancel ID R` | Follow, resume, or stop comparisons |
| `runs R` · `run show\|cancel\|delete EVALUATION_ID R` | One model's evaluation, with every trial |

`compare` flags:

| Flag | Default |
| --- | --- |
| `--harness H` (repeatable): `pi`, `codex`, `claude-code`, `mini-swe-agent`, `terminus-2`, `muse-code` | `pi` |
| `--thinking LEVEL`: `off`, `minimal`, `low`, `medium`, `high`, `xhigh`, `max` | the model's default |
| `--credential ID` | managed model |
| `--sandbox managed\|e2b\|modal\|daytona` and `--sandbox-credential ID` | managed sandbox |
| `--task RUN_ID/TASK_ID` (repeatable) | every approved task |
| `--skip-completed` | rerun everything |
| `--judge-credential ID` | required for tasks graded by an LLM judge |
| `--selection JSON\|@FILE` | a full [comparison body](/api#evaluate) in place of the flags |

## Inspect

| Command | Does |
| --- | --- |
| `results R` | Pass rate and cost per configuration, and every task, hardest first |
| `task results RUN_ID TASK_ID R` | Every configuration on one task, with failure explanations and the fairness verdict |
| `task explain RUN_ID TASK_ID R [--config KEY] [--model M --credential ID] [--wait]` | Explain a task's unexplained failures |
| `task audit RUN_ID TASK_ID R --model M --credential ID [--wait]` | Judge whether the task is `fair`, `unfair`, or `unclear` |
| `summaries R` | The latest Model Summaries report |
| `summaries create R --model M --credential ID [--config KEY ...] [--wait]` | Summarize how configurations differ |

`task explain` uses a managed model where the deployment offers one. Audits and summaries need a saved model API key.

## Publish

Only public repositories, and groups of them, can be released to selfbench.dev.

| Command | Does |
| --- | --- |
| `release preview R` | The settings, tasks, and coverage a release would publish |
| `release publish R [--setting KEY ... \| --all-settings] [--publish-tasks] [--publish-trials] [--publish-summaries]` | Release the preview it just read |
| `releases R` · `release withdraw RELEASE_ID R` | List or withdraw releases |

## Benchmarks and Groups

| Command | Does |
| --- | --- |
| `benchmarks` · `benchmark add\|show\|tasks\|remove ORG/NAME[@REF]` | Harbor registry datasets; evaluate one with `--benchmark ORG/NAME` |
| `groups` · `group show\|delete SLUG` | Repository groups; evaluate or release one with `--group SLUG` |
| `group create\|update SLUG --name NAME --member OWNER/NAME [--member ...]` | Pool connected repositories |

Benchmarks are never released.

## Operator

These take `SELFBENCH_API_TOKEN`, the deployment's own token, in place of an API key.

| Command | Does |
| --- | --- |
| `status\|cancel RUN_ID` · `list` | Generation runs |
| `download RUN_ID OUT.tar.gz` | A batch's Harbor export, checked against its SHA-256 |
| `grant create --label NAME --task ID [--task ID ...] [--days N] [--with-verifier]` | A customer's registry login for accepted tasks' images, shown once |
| `grant list` · `grant revoke GRANT_ID` | List or revoke grants |
