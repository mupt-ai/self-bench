## 1. Install the CLI

Needs Node.js 22 or later.

```bash
curl -fsSL https://raw.githubusercontent.com/mupt-ai/self-bench/main/scripts/install-cli.sh | sh
self-bench login
```

The installer puts `self-bench` in `~/.local/bin`, and says so if that folder isn't on your `PATH`. Re-run it to upgrade, or set `SELFBENCH_CLI_VERSION=0.3.15` to pin a version. If you installed with npm before, run `npm uninstall -g self-bench` so the new copy runs. `login` opens your browser to approve the CLI and pick a workspace.

## 2. Connect Credentials

Workspace admins connect a model and a sandbox under **Credentials**, or with `self-bench credential add`. See [Credentials](/concepts/credentials).

## 3. Run It

Each step works in the app or the CLI. Use the same repository name, `acme/app`, throughout.

| Step | In the app | With the CLI |
| --- | --- | --- |
| Connect a repository | **Repositories → Connect** | `self-bench repo connect acme/app` |
| Generate tasks | **Batch Generation** | `self-bench generate --repo acme/app --easy 2 --medium 4 --hard 2` |
| Review | **Dataset**: inspect, approve, reject | `self-bench tasks --repo acme/app --state needs_review`, then `task approve BATCH TASK --repo acme/app` |
| Revise | **Feedback** on a task | `self-bench task revise BATCH TASK --repo acme/app --feedback "…"` |
| Evaluate | **Run** | `self-bench compare --repo acme/app --model gpt-6.1-sol --harness pi` |
| Read results | **Results** | `self-bench results --repo acme/app` |
| Explain or audit | **Explain Failure**, **Audit Task** | `self-bench task explain BATCH TASK --repo acme/app --wait` |
| Publish | **Releases** (public repositories) | `self-bench release preview --repo acme/app`, then `release publish` |

Tasks are approved before they can be evaluated, and a comparison runs every approved task unless you name some. For the full command list, see [CLI](/cli/overview).
