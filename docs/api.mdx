Base URL `https://app.selfbench.dev`. Send `Authorization: Bearer $SELFBENCH_API_KEY` (or `X-API-Key`). Create keys under **Settings → API Keys**; the secret is shown once. A `read` key may only `GET`. A key acts as its owner, with the owner's workspace roles. Keys can be listed with a key but only minted or revoked from a signed-in browser, so a leaked key can't issue more keys.

```bash
curl https://app.selfbench.dev/api/me -H "Authorization: Bearer $SELFBENCH_API_KEY"
```

## Conventions

- **Scope.** Evaluation routes sit under `{scope}`: a repository or eval `/api/orgs/{org}/repos/{owner}/{name}` (an eval's owner is `evals`), a benchmark `/api/orgs/{org}/benchmarks/{dataset-org}/{dataset}`, or a group `/api/orgs/{org}/groups/{slug}`. `{repo}` is the repository form only.
- **Tasks** are named by batch and task ID, `{runId}/{taskId}`.
- **Configurations** are named by a setting `key`, shared by results, summaries, and releases.
- **Background work** returns `202`. Poll the matching `GET`.
- **Errors** are `{ "error": "…" }`: `400` invalid, `403` not allowed for this key, `404` not found, `409` wrong state.

## Request Bodies

Routes not listed here take no body.

| Route | Body |
| --- | --- |
| `POST /api/orgs/{org}/repos` | `{ fullName: "owner/name" }` |
| `PATCH {repo}` | `{ agentMinutes }` |
| `POST /api/orgs/{org}/evals` | `{ name }` |
| `POST /api/orgs/{org}/credentials` | `{ name, kind, value, tokenId?, teamId?, projectId?, endpoint? }` |
| `POST /api/api-keys` | `{ name, scope: "read" \| "write" }` (browser session) |
| `POST {repo}/batches` | `{ candidateCounts: { easy, medium, hard } (1–300 total), focus?, generation }` |
| `POST {repo}/tasks/from-pr` | `{ pr: number or URL, generation }` |
| `POST {repo}/tasks/from-scenario` | `{ title (≤120), scenario (≤20,000 chars), commit? (repositories only: SHA, branch, or HEAD), difficulty?: easy\|medium\|hard, attachments?: [{ name, content: base64 }] (≤20 files, 20 MB), generation }` |
| `PUT …/review` | `{ decision: "approve" \| "reject", note? }` (settled tasks only) |
| `POST …/feedback` | `{ feedback?, draft?: base64 tar.gz (≤22 MB), generation }` returns the revision |
| `POST {repo}/environments` | `{ environment: { name, packages?: [{ name, spec, directory? }], files?: [{ path, mode: "replace" \| "append" \| "delete", content? }] }, generation }` |
| `POST …/steering` | `{ feedback }` |
| `POST {scope}/evaluations/comparisons` | `{ id (UUID you generate; retries never start twice), models: [{ catalogId, credentialId, harnesses, thinking? }] (≤12), sandbox, sandboxCredentialId, tasks?: [{ runId, taskId }], skipCompleted?, judgeCredentialId?, conditions?: [{ name, skills?, instructions?, environment?, harnessOptions? }] (≤4), baseline? }` |
| `POST {scope}/evaluations/{id}/explain` | `{ runId, taskId, harness, explanation? }` |
| `POST {scope}/evaluations/audit` | `{ runId, taskId, audit: { credentialId, model } }` |
| `POST {scope}/evaluations/summaries` | `{ configurations: [keys] (≤12), summary: { credentialId, model } }` |
| `POST {repo}/releases` | `{ settings: [keys], head, fingerprint, publishTasks?, publishTrials?, publishSummaries? }` |
| `POST /api/orgs/{org}/benchmarks` | `{ reference: "org/name" or "org/name@ref" }` |
| `POST /api/orgs/{org}/groups` | `{ name, slug, description?, repositoryIds }` |

`generation` names the models, sandbox, and credentials for generation. Leave it out to use the managed models and sandbox, where the deployment offers them.

`credentialId` in a model choice is a saved credential's ID, or `managed-model`. `models[].harnesses` are `pi`, `codex`, `claude-code`, `mini-swe-agent`, `terminus-2`, or `muse-code`. `thinking` is `off`, `minimal`, `low`, `medium`, `high`, `xhigh`, or `max`.

## Evaluate

`POST {scope}/evaluations/comparisons` starts one **evaluation** per model, running every task on each harness as a trial. If the reply has `submissionError`, resume the same comparison with its `id`; it reuses the same evaluation IDs.

`conditions` runs every task again under each [condition](/concepts/how-it-works#conditions) beside the tasks as they are; `baseline: false` runs only the conditions. A condition's `environment` is an environment's id from `{repo}/environments`. Its `harnessOptions` maps a harness to options from the catalog's `harnessOptions`, such as `{"claude-code": {"max_turns": 30, "config": {…}}}`; a condition with them runs only on those harnesses. Results report each condition as its own configuration.

Use `GET {scope}/evaluations/results` for scores rather than adding up trials. Results count each configuration's latest scored result on each counted task: a repository's accepted tasks, or a benchmark's tasks. Errors, cancellations, and trials still running don't count.

## Model Costs

Trials call their model through SelfBench's gateway, which uses the workspace credential and records each call's cost: the provider's own charge where it reports one, else the model's list price. A trial with an unpriced call shows its cost as incomplete. The credential never reaches the agent, which gets a short-lived key for its one model.
