An evaluation runs a model and harness against approved tasks in fresh sandboxes. The agent sees the base repository and instruction, not the held-out tests or reference solution.

## Configure a Comparison

Open your repository's **Run** page. Select approved tasks, add model and harness pairs, choose a sandbox, and supply the required workspace credentials. Model choices and reference pricing come from the app's catalog. **Run Full Comparison** executes every selected task for each model/harness pair; **Run Missing Tasks** skips completed trials for those pairs. Each trial is a separate Harbor run.

A ChatGPT, Claude or Meta sign-in or a model API key can run evaluations, subject to harness compatibility: each sign-in runs only its own CLI (Codex, Claude Code or Muse Code). Every API key and the ChatGPT and Claude sign-ins reach their model through SelfBench's model gateway, so a Meta key runs every harness. Each row offers the reasoning levels its model lists that every one of its harnesses accepts. Modal, E2B, or Daytona can run the tasks. See [Quickstart](/quickstart) for credentials and [Task Generation](/concepts/task-generation#what-the-evaluated-agent-sees) for what the evaluated agent can access.

## Use a Custom Router

Add a **Custom Endpoint** credential with the router's API key and HTTPS **base URL**, not the URL of a specific API method. Its hostname must be allowed by the deployment's `SELFBENCH_CUSTOM_MODEL_HOSTS` setting. Each harness calls the endpoint in its own protocol: Pi its OpenAI-compatible Chat Completions API, Codex its Responses API, and Claude Code its Anthropic Messages API, at the base URL without `/v1`. Codex sends no reasoning effort, so the endpoint uses its own default.

A custom endpoint's call is priced from what its response reports. A router that reports the price it billed for a call (Ramp's Responses API) is taken as reported. Otherwise the call is priced at the list rates of the model its response names, so a router that answers each call from a different model (Shift-1) is priced call by call. A call whose model the catalog does not price leaves its trial without a cost.

| Router | Base URL | Model ID | Harnesses |
| --- | --- | --- | --- |
| Applied Compute Shift-1 | `https://api.shift.ac/v1` | `shift-1` | Codex (GPT-6 Astra or GPT-6.1 Sol), Claude Code (Claude Opus 5.5 or Sonnet 5.5) |
| Ramp's Router | `https://api.router.com/v1` | a routing model from its `/v1/models` | Codex, Claude Code |

Shift-1 runs on your own OpenAI and Anthropic keys, which you connect at shift.ac; the Shift key goes in the credential.

For Dari, add a **Dari** credential with your API key. It runs your default router; to run another, paste that router's address, such as `https://routing.dari.dev/rtr_…`, into **Router URL**. An address ending in `/chat/completions` is accepted and trimmed. It runs **Pi**, **Codex**, or **Claude Code**. Each trial's cost is the price Dari returned for its calls; a trial with a call Dari did not price (one cut off by the time limit) has no cost.

With a **Custom Endpoint** credential instead, use `https://routing.dari.dev/v1` for your default router, or `https://routing.dari.dev/<router_id>` for a specific router, and enter `dari/routing` as the custom model ID. Do not include `/chat/completions` or `/responses` in the credential's endpoint: the harness appends the API method itself.

To evaluate Jev through Dari, create a separate Dari router with Jev as its selector and use that router's base URL. The API key and model ID stay the same. Separate credentials for the Dari and Jev router URLs let you compare them without changing your default router.

## Read Results

Open **Results** to compare accuracy and model API cost per task. Inspect a trial to read its transcript, scores, and artifacts. The Pareto frontier highlights settings that are not beaten on both accuracy and cost.

To share aggregate results for a public repository, [publish a release](/guides/publish-results). Per-task results stay private unless you choose to publish them with the release.
