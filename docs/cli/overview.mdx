The `self-bench` CLI covers everything the app does with your evals, over the [Workspace API](/api-reference/workspace).

## Set Up

```bash
npm install -g self-bench            # Node.js 22 or later
self-bench login                     # sign in through your browser and pick a workspace
self-bench credential add            # connect a model sign-in or key, and a sandbox
```

`login` approves the CLI in your browser and saves a personal API key to `~/.config/self-bench/config.json`, readable only by you. On a remote machine, the browser can't reach the CLI; paste the address it lands on into the login page instead. `logout` revokes the key.

In CI, skip `login`: set `SELFBENCH_API_KEY` to a key from **Settings → API Keys**, and `SELFBENCH_ORG` to the workspace. `SELFBENCH_API_URL`, or `login --api-url`, points the CLI at a self-hosted or local deployment; it defaults to `https://app.selfbench.dev`.

## The Eval Loop

```bash
R=acme/app

# Build: connect a repository and generate tasks from its merged PRs
self-bench repo connect $R
self-bench generate --repo $R --easy 2 --medium 4 --hard 2

# Review: read each task, revise or approve it
self-bench tasks --repo $R --state needs_review
self-bench task pull BATCH TASK ./task --repo $R
self-bench task revise BATCH TASK --repo $R --feedback "Test the empty-file case too."
self-bench task approve BATCH TASK --repo $R

# Evaluate: run models on every approved task
self-bench compare --repo $R --model gpt-6.1-sol --model claude-opus-5-5 --harness pi
self-bench comparisons --repo $R

# Inspect: scores, then one task in depth
self-bench results --repo $R
self-bench task results BATCH TASK --repo $R
self-bench task explain BATCH TASK --repo $R --wait
self-bench task audit BATCH TASK --repo $R --model gpt-6.1-sol --credential KEY_ID --wait

# Publish (public repositories): preview, then release to selfbench.dev
self-bench release preview --repo $R
self-bench release publish --repo $R
```

For tasks you describe instead of PRs, see [Author Scenarios](/guides/author-scenarios). For a Harbor dataset, use `self-bench benchmark add` and pass `--benchmark ORG/NAME` in place of `--repo`.

## Conventions

- **Workspace.** Commands act in the workspace `login` chose. `org use` changes it; `--org` overrides it once.
- **Scope.** Commands act on `--repo OWNER/NAME` (an eval is `evals/NAME`), `--benchmark ORG/NAME`, or `--group SLUG`.
- **Tasks** are named by their batch and ID: `RUN_ID TASK_ID`, or `RUN_ID/TASK_ID` in `--task`.
- **Configurations** (model, reasoning, harness) are named by the `KEY` that `results` prints. `summaries create --config` and `release publish --setting` take it.
- **Credentials.** Commands use managed models and sandboxes unless you pass a saved credential's ID from `self-bench credentials`.
- **Output.** Lists print tables on a terminal and JSON when piped or with `--json`, so `self-bench results --repo $R | jq` works.
- **Waiting.** Explanations, audits, and summaries run in the background. `--wait` waits for the answer and prints it.

Every command is listed in [Commands](/cli/commands) and `self-bench help`.
