`S` is any [benchmark](/cli/overview#benchmarks): `--repo OWNER/NAME`, `--custom NAME`, `--public ORG/NAME`, or `--group SLUG`.

| Command | Does |
| --- | --- |
| `run models S` | Models an evaluation can use |
| `run models S --harness AGENT` | Options a [saved harness](/cli/harnesses) can set on `AGENT` |
| `run create S --model ID [--model ID ...]` | Start one run per model on every approved task |
| `run list S` · `run show\|cancel\|delete ID S` | A run, with every trial |
| `run batch list S` · `run batch show\|resume\|cancel ID S` | Runs started together: follow, resume, or stop them |

`run create` starts one **run** per model, together as a **batch**, and each run runs every task on each harness as a **trial**. Compare runs on [Results](/cli/inspect). For scores, read [`results`](/cli/inspect) rather than adding up trials.

## `run create`

```bash
self-bench run create --repo acme/app \
  --model claude-opus-5-5 --model gpt-6.1-sol --harness claude-code --harness codex --thinking high
# Batch BATCH_ID
# EVALUATION  MODEL            SETUP     HARNESSES           STATUS   TRIALS
# …           claude-opus-5-5  Baseline  claude-code, codex  running  0/48
```

| Flag | Default |
| --- | --- |
| `--model ID` (repeatable): a model `run models` lists | required |
| `--harness AGENT` (repeatable): `pi`, `codex`, `claude-code`, `mini-swe-agent`, `terminus-2`, `muse-code` | `pi` |
| `--thinking LEVEL`: `off`, `minimal`, `low`, `medium`, `high`, `xhigh`, `max` | the model's default |
| `--credential ID`: a [saved credential](/cli/account#credentials) | the managed model |
| `--sandbox managed\|e2b\|modal\|daytona\|vercel` and `--sandbox-credential ID` | the managed sandbox |
| `--task TASK` (repeatable) | every approved task |
| `--skip-completed`: leave out tasks a configuration already finished | run everything again |
| `--judge-credential ID` | required for tasks graded by an LLM judge |
| `--saved-harness ID` (repeatable): a [saved harness](/cli/harnesses) | none |
| `--environment ID` (repeatable): a repo [environment](/cli/environments) | none |
| `--no-baseline`: leave out the tasks and agents as they are | the baseline runs too |
| `--selection JSON\|@FILE` | a full [batch body](/api/evaluate#request-body) in place of the flags |

Every task runs again with each saved harness, in each environment, and with each harness in each environment (at most 12), beside the baseline; see [Harnesses and Environments](/api/evaluate#harnesses-and-environments). The older `--saved-condition`, `--condition`, and `--harness-option` flags still work.

A harness with a subagent model runs each model as the orchestrator and the subagent model for delegated work, on the credential the harness names; see [Subagent Models](/api/evaluate#subagent-models).

## Following a Batch

`run batch show ID` prints each evaluation's progress. If the reply names a submission error, `run batch resume ID` starts what didn't start, with the same evaluation IDs. `run batch cancel ID` stops every evaluation in it; `run cancel ID` stops one.

```bash
self-bench run batch list --repo acme/app
self-bench run show EVALUATION_ID --repo acme/app --json
```
