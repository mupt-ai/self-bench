`S` is any [benchmark](/cli/overview#benchmarks). `TASK` is `RUN_ID/TASK_ID`.

| Command | Does |
| --- | --- |
| `results S` | Pass rate and cost per configuration, and every task, hardest first |
| `task results TASK S` | Every configuration on one task, with failure explanations and the fairness verdict |
| `task explain TASK S [--config KEY] [--model ID --credential ID] [--wait]` | Explain why a task's failures failed |
| `task audit TASK S --model ID --credential ID [--wait]` | Judge whether the task is `fair`, `unfair`, or `unclear` |
| `summary show S` | The latest Model Summaries report |
| `summary create S --model ID --credential ID [--config KEY ...] [--wait]` | Summarize how configurations differ |

## `results`

Results count each configuration's latest scored result on each counted task: a repo or custom benchmark's approved tasks, or a public benchmark's tasks. Errors, cancellations, and trials still running don't count. `BLOCKED` counts tasks a provider's cyber-safety classifier blocked, scored as failures.

```bash
self-bench results --repo acme/app
# 24 tasks
#
# CONFIGURATION                 PASS RATE  PASSED  BLOCKED  COST / TASK  KEY
# Claude Opus 5.5 · high · pi   66.7%      16/24   1/24     $0.84        a1b2…
```

## `task explain`

Asks a model to explain each failure on a task that has no explanation yet; `--config KEY` explains one configuration's. It uses a managed model where the deployment offers one; `--model` and `--credential` pick another.

## `task audit`

Judges whether a task is fair from its attempts: `fair` when a capable engineer could pass its hidden tests from the instruction and repository alone, `unfair` when failures come from the task itself (tests that check details the instruction never asked for), `unclear` otherwise. It needs a saved model API key. `task results` shows the latest verdict, and [`feedback --from-audit`](/cli/review#feedback) sends it to the task's author.

```bash
self-bench task audit 6f1c2e9a/fix-invoice-rounding --repo acme/app \
  --model claude-opus-5-5 --credential CREDENTIAL_ID --wait
```

## `summary create`

Writes a report of how configurations differ, from up to 12 of them: the `--config` keys, or the top scorers without any. It needs a saved model API key.
