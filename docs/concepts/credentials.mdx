Workspace admins connect credentials; every run in the workspace uses them. Evaluations need a model credential and a sandbox credential. Connect Claude, ChatGPT, Meta Muse and OpenCode Go plans, and model API keys for evaluations, in the app with **Connect with Dari** (Settings → Credentials); Dari holds them, and SelfBench never sees the plan's token or the key. A benchmark's LLM judge calls with a Dari connection too, one with an API key or a plan any app can use (a Claude or Muse plan alone serves only its own coding agent): SelfBench's gateway forwards each of the judge's calls to Dari for the model it names, such as `gpt-5-mini` or `openai/gpt-5-mini`, and Dari's refusal (a model the connection doesn't serve, a plan at its limit) is the call's error. Provider and gateway API keys saved before Connect with Dari still judge, and stay listed under **Other Model Credentials**.

A workspace has one Dari connection, one credential. Generation offers the models it serves for any app, the same as evaluations. The Run page offers every model its plans and keys serve, as Dari lists them: a model only a Claude plan serves runs on Claude Code, one only a Muse plan serves on Muse Code, and any other on any harness (Muse Code too, for a Meta key's models). An OpenRouter or Vercel AI Gateway key serves every model of its gateway. The list is what the connection shared when it was connected: to change it, choose **Update Plans**, which puts the new approval on the same credential and ends the old one on Dari. Deleting a connection ends it on Dari too.

| Kind | Runs |
| --- | --- |
| Connect with Dari (`dari-link`) | Evaluations on the models the connection's plans and keys serve, and generation on any of them except a Claude or Muse plan's own models (generation runs Pi, which those plans do not serve) |
| `openai`, `anthropic`, `meta`, `openrouter`, `vercel-ai-gateway`, `dari` | Model API keys: evaluations on any harness the model supports, and generation |
| `custom` (`--endpoint`) | A router or endpoint you name; see below |
| `e2b`, `modal`, `daytona`, `vercel` | Sandboxes: each generates tasks, checks them in Harbor, and runs evaluations |

Every pasted model key reaches its model through SelfBench's gateway, so the credential never enters the agent's sandbox.

## Custom Routers

Models Dari does not serve run on a **Custom Endpoint** (Settings → Credentials → **Add Endpoint**). Use a Custom Endpoint credential with the router's HTTPS base URL, not a method's URL. The hostname must be in the deployment's `SELFBENCH_CUSTOM_MODEL_HOSTS`. Each harness calls the endpoint in its own protocol: Pi uses Chat Completions, Codex uses Responses, and Claude Code uses Messages. Give the base URL without `/v1` for Claude Code, and without `/chat/completions` or `/responses` for any harness.

| Router | Base URL | Model ID | Harnesses |
| --- | --- | --- | --- |
| Applied Compute Shift-1 | `https://api.shift.ac/v1` | `shift-1` | Codex, Claude Code. Needs your own OpenAI and Anthropic keys, connected at shift.ac |
| Ramp Router | `https://api.router.com/v1` | a routing model from `/v1/models` | Codex, Claude Code |
| Fireworks Fire Pass | `https://api.fireworks.ai/inference/v1` | a router, such as `accounts/fireworks/routers/kimi-fast-latest` | Pi, Codex, Claude Code. Use your `fpk_…` key |
| Baseten Grid | `https://inference.baseten.co/v1` | a Grid route's name | Pi, plus Codex and Claude Code on routes that serve them. Grid is in preview |
| Baseten Model APIs | `https://inference.baseten.co/v1` | a model slug, such as `zai-org/GLM-5.3` | Pi, Codex, Claude Code |
| Dari | `https://routing.dari.dev/v1`, or `https://routing.dari.dev/<router_id>` | `dari/routing` | Pi, Codex, Claude Code. Use the **Dari** credential, with **Router URL** for another router |

A call is priced from what the router reports. If it reports none, it is priced at the list rate of the model its response names. A call whose model the catalog doesn't price leaves its trial without a cost.

To evaluate Jev through Dari, create a Dari router with Jev as its selector and add its base URL as a separate credential. The key and model ID stay the same.
